Part 1 · Composite

The Composite

public class Combo implements MenuComponent {
    private String name;
    private double discount;
    private List<MenuComponent> children = new ArrayList<>();
    public void add(MenuComponent c) { children.add(c); }

    public double getPrice() {
        double sum = 0;
        for (MenuComponent c : children)            sum += c.getPrice();        return sum * (1 - discount);
    }

    public void print(String indent) {
        System.out.println(indent + name);
        for (MenuComponent c : children)            c.print(indent + "  ");    }
}
  • Holds a list of the interface — not of MenuItem
  • So a child can be another Combo
  • c.getPrice() — the child decides how

The recursion lives here — the client never sees it.

Part 2 · State

The naive way: a switch in every method

public void cancel() {
    switch (status) {        case CREATED:   status = CANCELLED; break;
        case PAID:      refund();
                        status = CANCELLED; break;
        case PREPARING: if (withinGracePeriod()) {
                            refund();
                            status = CANCELLED;
                        } break;
        default: throw new IllegalStateException();
    }
}
// ...and again in pay(), accept(),
//    pickedUp(), delivered()
  • 6 states × 6 events in one class
  • New state → edit every method
  • Each state's logic is scattered across the class

Violates SRP and OCP.

Part 2 · State

The pattern

  • Context holds the current state and delegates to it
  • State — one method per event
  • Concrete state — the behavior of one state, and where to go next
public void cancel() {
    state.evCancel(this);
}

Part 2 · State

The base state: "no arrow" by default

public abstract class OrderState {
    void evPaid(Order o)          { illegal("evPaid"); }
    void evPaymentFailed(Order o) { illegal("evPaymentFailed"); }
    void evAccept(Order o)        { illegal("evAccept"); }
    void evPickedUp(Order o)      { illegal("evPickedUp"); }
    void evDelivered(Order o)     { illegal("evDelivered"); }
    void evCancel(Order o)        { illegal("evCancel"); }

    private void illegal(String ev) {
        throw new IllegalStateException(
            ev + " not allowed in " +
            getClass().getSimpleName());
    }
}
  • Each state overrides only its arrows
  • Everything else is blocked automatically

An interface works too — but then every state must implement all 6 events.

Part 2 · State

Created and Paid

Created 
class CreatedState extends OrderState {
    void evPaid(Order o) {
        o.setState(new PaidState());
    }
    void evPaymentFailed(Order o) {
        o.showError();       // stay here
    }
    void evCancel(Order o) {
        o.setState(new CancelledState());
    }
}
Paid 
class PaidState extends OrderState {
    void evAccept(Order o) {
        o.setState(new PreparingState());
    }
    void evCancel(Order o) {
        o.refund();
        o.setState(new CancelledState());
    }
}

Same event, evCancel — different behavior per class.

Part 2 · State

Preparing: guard, action, transition

Preparing 
class PreparingState extends OrderState {
    void evPickedUp(Order o) {
        o.setState(new OutForDeliveryState());
    }
    void evCancel(Order o) {
        if (o.withinGracePeriod()) {     // guard            o.refund();                  // action            o.setState(new CancelledState()); // transition
        }
    }
}
The rest 
class OutForDeliveryState extends OrderState {
    void evDelivered(Order o) {
        o.notifyCustomer();
        o.setState(new DeliveredState());
    }
}

class DeliveredState extends OrderState { }
class CancelledState extends OrderState { }

Final states override nothing — every event is blocked.

Part 2 · State

The Order (Context)

public class Order {
    private OrderState state = new CreatedState();
    void setState(OrderState s) { state = s; }

    public void pay()       { state.evPaid(this); }
    public void accept()    { state.evAccept(this); }
    public void pickedUp()  { state.evPickedUp(this); }
    public void delivered() { state.evDelivered(this); }
    public void cancel()    { state.evCancel(this); }

    void refund()               { ... }
    void notifyCustomer()       { ... }
    void showError()            { ... }
    boolean withinGracePeriod() { ... }
}
  • No switch, no if (status == ...)
  • Every public method is one line
  • Passes this so the state can change it

Part 2 · State

What we gained

SRP

Each state's behavior lives in one small class.

OCP

Scheduled orders? Add ScheduledState, change one arrow in CreatedState. Nothing else.

Safe

Illegal events can't slip through — a courier can't pick up a cancelled order.

Recitation 4: these states have no fields — each could be a Singleton instead of new on every transition. Data that must survive a transition belongs in the Order.
